> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status: executing.** Tasks 1-8 below (the `Frank.Rdf` package itself, through the sample) never touched HTTP serving, so they were always safe to run independently. The plan was written alongside two undone Frank-core prerequisites for the *next* phase (the tic-tac-toe follow-on plan's content-negotiation work) — [frank-fs/frank#481](https://github.com/frank-fs/frank/issues/481) (no shared, resource-scoped Link-header mechanism) and [frank-fs/frank#482](https://github.com/frank-fs/frank/issues/482) (Frank's content-negotiation approach needed re-evaluating before building on it) — both of which have since landed (resource-scoped `link` operation on `resource { }`; the `negotiate { }` CE on `MediaTypeHeaderValue`). See the design doc's *Serving it over HTTP* section for the resulting shape. The tic-tac-toe follow-on plan itself is still unwritten — out of scope for this plan, see below — but is no longer blocked on Frank core.

**Goal:** A new `Frank.Rdf` package providing an `rdf { }` computation expression for hand-authoring RDF triples, serialized to JSON-LD in expanded form.

**Architecture:** Two files. `RdfTypes.fs` defines a flat triple model (`Node`, `Literal`, `Value`, `Doc`, `Description`) mirroring RDF's own subject/predicate/object shape rather than JSON-LD's document shape. `Rdf.fs` provides two computation expressions that mirror Frank core's own `handler { }` → `get (handler {...})` composition pattern exactly: `describe subject { typ; property }` is fully self-contained and produces a plain `Description`; `rdf { }`'s `about` operation consumes that value the same way `resource { }`'s `get` consumes a `HandlerDefinition`. No `Combine`/`Delay` on either builder. `Doc.toGraph`/`Doc.writeJsonLd` wrap dotNetRDF for the actual graph construction and JSON-LD writing, with `Doc.toJsonLd` a thin string-returning convenience wrapper.

**Tech Stack:** F# 8.0+, .NET 8.0/9.0/10.0 multi-targeting, dotNetRdf.Core 3.5.1, Expecto.

**Design doc:** `docs/superpowers/specs/2026-07-30-frank-rdf-design.md`

## Global Constraints

- `src/Frank.Rdf/` targets `net8.0;net9.0;net10.0`. **No `ProjectReference` to `Frank`, no `FrameworkReference` to `Microsoft.AspNetCore.App`.** One NuGet dependency: `PackageReference dotNetRdf.Core 3.5.1` (exact version, matching the only prior use of this library in this codebase's history).
- Every `.fs` file gets a matching `.fsi` immediately above it in `<Compile>` order (`CLAUDE.md`). Update both together in every task.
- `Node`, `Literal`, `Value` are `[<RequireQualifiedAccess>]`. Every reference to a case is qualified: `Node.Iri`, `Node.Blank`, `Literal.String`, `Value.Node`, `Value.Literal`.
- `Node.blank ()` MUST mint a `System.Guid`-based label, never a per-`Doc` counter — this is what makes `Doc.merge` (Task 7) safe, and is load-bearing, not cosmetic.
- Output is **expanded-form JSON-LD only.** No `@context` in output, no compaction. Do not add a compaction step.
- `resolveIri`/`validatePrefixes` (Task 2) are `internal`, not `private` — the test project needs to call them directly, via `InternalsVisibleTo` (set up in Task 1).
- Test framework is **Expecto**, matching every other Frank test project (`test/Frank.JsonHome.Tests`, `test/Frank.Auth.Tests`) — not xUnit/NUnit.
- Commit after every task (this repo is trunk-based — commit directly, no PR).

```fsharp
namespace Frank.Rdf

open System

/// A subject, or a reference-valued object: an absolute IRI (or a "prefix:local" CURIE), or a blank node.
[<RequireQualifiedAccess>]
type Node =
    | Iri of string
    | Blank of string

/// An RDF literal value.
[<RequireQualifiedAccess>]
type Literal =
    | String of string
    | Int of int
    | Bool of bool
    | DateTime of DateTimeOffset

/// The object of a triple: either a reference to another resource, or a literal.
[<RequireQualifiedAccess>]
type Value =
    | Node of Node
    | Literal of Literal

/// A flat set of RDF triples plus the namespace prefixes used to author them.
type Doc =
    { Prefixes: (string * string) list
      Statements: (Node * string * Value) list }

    static member Empty: Doc

/// Statements about one subject, produced by `describe { }` before being attached to a `Doc` via `about`.
type Description =
    { Subject: Node
      Statements: (string * Value) list }

/// Mints RDF nodes.
module Node =
    /// A fresh blank node with a globally-unique label (a GUID) -- so that Doc.merge (see Rdf.fsi)
    /// can never collide two unrelated blank nodes minted by two independently-built documents.
    val blank: unit -> Node
```

### Task 2: CURIE resolution and prefix-conflict validation

**Files:**
- Modify: `src/Frank.Rdf/Frank.Rdf.fsproj` (add `Rdf.fsi`/`Rdf.fs` entries)
- Create: `src/Frank.Rdf/Rdf.fsi`, `src/Frank.Rdf/Rdf.fs`
- Modify: `test/Frank.Rdf.Tests/Frank.Rdf.Tests.fsproj` (add `PrefixResolutionTests.fs`)
- Create: `test/Frank.Rdf.Tests/PrefixResolutionTests.fs`

**Interfaces:**
- Consumes: `Node`, `Literal`, `Value`, `Doc`, `Description` (Task 1).
- Produces:
  - `internal resolveIri : prefixes:(string * string) list -> s:string -> string` — resolves a CURIE against declared prefixes, or passes an absolute IRI through unchanged; raises on anything else.
  - `internal validatePrefixes : prefixes:(string * string) list -> unit` — raises if the same prefix name is declared with two different URIs.

**Background you need:**

This is the one place in the package worth being genuinely careful about, because the obvious-looking implementation is wrong. `Node.Iri` values are used for two different things: CURIEs like `"schema:Game"` (needs resolving against a declared prefix) and already-absolute IRIs like `"https://tictactoe.example/games/1"` or `"http://www.wikidata.org/entity/Q210339"` (needs passing through as-is). The tempting way to tell them apart is `System.Uri.IsWellFormedUriString(s, UriKind.Absolute)` — check "is this already a valid absolute URI" first, and only try CURIE resolution if that's false.

**That's backwards, and it's a real bug, not a style nitpick.** `.NET`'s `Uri` parser doesn't require a *recognized* scheme — `"schema:Game"` parses as a syntactically well-formed absolute URI with scheme `"schema"` and opaque part `"Game"` (the same way `"urn:isbn:123"` or `"mailto:x@y.com"` do). If you check well-formedness first, `"schema:Game"` — the single most common kind of value this whole CE exists to construct — gets treated as an opaque absolute IRI and used completely unresolved (literally `"schema:Game"` ends up in the graph, instead of `"https://schema.org/Game"`), with **no error, no warning, silently wrong output.**

The fix: check whether the text before the first `:` matches a **declared** prefix first. If it does, resolve it — that's unambiguous, since declaring a prefix is explicit author intent. Only if it *doesn't* match a declared prefix, fall back to checking whether the whole string is already a well-formed absolute URI. Only if neither is true, it's an error.

```fsharp
namespace Frank.Rdf

/// Resolves a CURIE ("prefix:local") against declared prefixes, or passes an absolute IRI through
/// unchanged. A declared prefix always takes priority over "is this already a well-formed URI" --
/// see the comment on the .fs implementation for why the other order is a real bug, not a style choice.
/// Raises if the text before the colon isn't a declared prefix and the whole string isn't a
/// well-formed absolute URI either. Raises if there's no colon at all.
internal val resolveIri: prefixes: (string * string) list -> s: string -> string

/// Raises if the same prefix name appears more than once with different URIs.
internal val validatePrefixes: prefixes: (string * string) list -> unit
```

- [ ] **Step 4: Write `Rdf.fs`**

```fsharp
namespace Frank.Rdf

open System

let internal resolveIri (prefixes: (string * string) list) (s: string) : string =
    match s.IndexOf ':' with
    | -1 -> failwithf "Frank.Rdf: '%s' is neither an absolute IRI nor a CURIE (no ':')" s
    | i ->
        let prefix = s.Substring(0, i)

        match prefixes |> List.tryFind (fun (p, _) -> p = prefix) with
        | Some(_, ns) -> ns + s.Substring(i + 1)
        | None ->
            if Uri.IsWellFormedUriString(s, UriKind.Absolute) then
                s
            else
                failwithf "Frank.Rdf: undeclared prefix '%s' in '%s'" prefix s

let internal validatePrefixes (prefixes: (string * string) list) : unit =
    prefixes
    |> List.groupBy fst
    |> List.iter (fun (prefix, entries) ->
        let uris = entries |> List.map snd |> List.distinct

        if uris.Length > 1 then
            failwithf "Frank.Rdf: prefix '%s' declared with conflicting URIs: %s" prefix (String.concat ", " uris))
```

```fsharp

/// rdf:type, as an absolute IRI. `typ` asserts a statement with this predicate directly, never
/// resolved through a declared prefix -- it's a universal RDF constant, not app vocabulary.
val RdfTypeIri: string

/// Builds a `Description`: statements about one subject, to be attached to an `rdf { }` document
/// via `about`. Self-contained -- mirrors Frank core's `HandlerBuilder`/`handler { }` exactly: one
/// accumulator, no Combine/Delay, `Run` returns a plain value.
[<Sealed>]
type DescribeBuilder =
    new: subject: Node -> DescribeBuilder
    member Yield: unit -> Description
    member Run: d: Description -> Description

    [<CustomOperation("typ")>]
    member Typ: d: Description * curie: string -> Description

    [<CustomOperation("property")>]
    member PropertyString: d: Description * predicate: string * value: string -> Description

    [<CustomOperation("property")>]
```

**Background you need:**

dotNetRDF (`VDS.RDF`) node-creation API used here, verified against the library's own docs:
- `graph.CreateUriNode(uri: System.Uri) : IUriNode` — for an already-resolved absolute IRI.
- `graph.CreateBlankNode(id: string) : IBlankNode` — the **string-parameterized** overload, not the parameterless one: reusing the same `id` string returns the same blank node within the graph, which is exactly what's needed since `Node.Blank guid` values are compared for equality by their GUID.

- `value.ToLiteral(graph)` — extension methods in `VDS.RDF` (brought into scope by `open VDS.RDF`) covering `int`, `bool`, `System.DateTimeOffset`, and more, producing a correctly XSD-typed literal node without hand-building datatype URIs.
- `graph.Assert(Triple(s, p, o))` — there is no direct 3-argument `Assert(subject, predicate, object)` overload; construct a `Triple` first.
- `graph.NamespaceMap.AddNamespace(prefix: string, uri: System.Uri)` — registers a prefix on the graph. This has no effect on expanded-form JSON-LD output (which never uses prefixes), but costs nothing and keeps the graph accurately reflecting its declared vocabulary for any future non-expanded/non-JSON-LD writer.

```fsharp
open VDS.RDF

module Doc =
    let private toGraphNode (graph: Graph) (prefixes: (string * string) list) (node: Node) : INode =
        match node with
        | Node.Iri s -> graph.CreateUriNode(Uri(resolveIri prefixes s)) :> INode
        | Node.Blank id -> graph.CreateBlankNode(id) :> INode

    let private toLiteralNode (graph: Graph) (literal: Literal) : INode =
        match literal with
        | Literal.String s -> graph.CreateLiteralNode(s) :> INode
        | Literal.Int i -> i.ToLiteral(graph)
        | Literal.Bool b -> b.ToLiteral(graph)
        | Literal.DateTime dt -> dt.ToLiteral(graph)

    let private toObjectNode (graph: Graph) (prefixes: (string * string) list) (value: Value) : INode =
        match value with
        | Value.Node n -> toGraphNode graph prefixes n
        | Value.Literal l -> toLiteralNode graph l

    let toGraph (doc: Doc) : Graph =
        validatePrefixes doc.Prefixes

        let graph = Graph()

        for prefixName, uri in doc.Prefixes do
            graph.NamespaceMap.AddNamespace(prefixName, Uri(uri))

        for subject, predicate, value in doc.Statements do
            let s = toGraphNode graph doc.Prefixes subject
            let p = graph.CreateUriNode(Uri(resolveIri doc.Prefixes predicate))
            let o = toObjectNode graph doc.Prefixes value
            graph.Assert(Triple(s, p, o)) |> ignore

        graph
```

**Background you need:**

`VDS.RDF.Writing.JsonLdWriter` operates on an `ITripleStore`, not a single `IGraph` directly — its only public method is `Save(store: ITripleStore, output: TextWriter, leaveOpen: bool)`. Wrap the graph in a `TripleStore` first. Output is expanded form (no `@context`) by construction — there is no option to request compact form, which matches the design doc's decision to use expanded form only.

`writeJsonLd` is the real primitive: it takes the caller's own `TextWriter`, so a response handler can pass one wrapping `ctx.Response.Body` directly and skip materializing the whole document as a `string` before writing it out — one fewer full copy at the app/response boundary (see the design doc's *Serialization* section for why this doesn't extend to true end-to-end streaming: dotNetRDF's `JsonLdWriter` itself builds an in-memory JSON tree via Newtonsoft's LINQ-to-JSON before emitting any text, regardless of what `TextWriter` it's given). Pass `leaveOpen = true` always — this function never owns the writer it's given, so it must never dispose it. `toJsonLd` is a convenience wrapper over `writeJsonLd` using an internal `StringWriter`, kept because the round-trip tests below (and any caller that genuinely needs the whole string) still need one.

For the round-trip check: `VDS.RDF.Parsing.JsonLdParser` has a `Load(store: ITripleStore, input: TextReader)` overload. Graph isomorphism is `graph1.Equals(graph2)` — `IGraph`'s `Equals(Object)` override *is* the isomorphism check (not reference equality), per dotNetRDF's own documentation.

```fsharp
        store.Add(graph)
        JsonLdWriter().Save(store, writer, true)

    let toJsonLd (doc: Doc) : string =
        use writer = new StringWriter()
        writeJsonLd doc writer
        writer.ToString()
```

```fsharp
module Sample.Rdf.Program

open System.Text
open System.IO
open Microsoft.AspNetCore.Http
open Frank.Builder
open Frank.Rdf

// A tiny in-memory "database" -- just enough to have more than one game to curl.
let private games = dict [ "1", "Tic-tac-toe"; "2", "Connect Four" ]

// Shared across every game's document: who publishes this API. Built once and merged into
// each per-game document via `include` -- a genuine reason to merge (facts every resource
// wants to assert), demonstrating Doc.merge for real rather than contriving one.
let private publisher = Node.Iri "https://frank-fs.github.io/#organization"

let private publisherDoc =
    rdf {
        prefix "schema" "https://schema.org/"
        about (describe publisher { typ "schema:Organization"; property "schema:name" "Frank" })
    }

let private gameDoc (baseUri: string) (id: string) (name: string) : Doc =
    let gameUri = Node.Iri $"{baseUri}/games/{id}"
    let players = Node.Iri $"{baseUri}/games/{id}#players"

    let doc =
        rdf {
            prefix "schema" "https://schema.org/"

            about (
                describe gameUri {
                    typ "schema:Game"
                    property "schema:name" name
                    property "schema:numberOfPlayers" players
                    property "schema:publisher" publisher
                }
            )

            about (describe players { typ "schema:QuantitativeValue"; property "schema:value" 2 })
        }

    Doc.merge doc publisherDoc

let private getGame: RequestDelegate =
    RequestDelegate(fun ctx ->
        task {
            let id = string ctx.Request.RouteValues.["id"]

            match games.TryGetValue id with
            | true, name ->
                let baseUri = $"{ctx.Request.Scheme}://{ctx.Request.Host}"
                ctx.Response.ContentType <- "application/ld+json"
                use writer = new StreamWriter(ctx.Response.Body, Encoding.UTF8, leaveOpen = true)
                Doc.writeJsonLd (gameDoc baseUri id name) writer
                do! writer.FlushAsync()
            | false, _ -> ctx.Response.StatusCode <- 404
        })

let private gameResource = resource "/games/{id}" { get getGame }

[<EntryPoint>]
let main args =
    webHost args {
        useDefaults
        resource gameResource
    }

    0
```
